Le planning des 48 heures

H0

Heures 0-4 : Base de données

Définis 3-5 tables Supabase. Crée les tables avec types et relations. Teste avec des données de test.

H4

Heures 4-10 : API Routes

Crée les routes essentielles : upload, traitement IA, récupération des résultats. Testables avec curl.

H10

Heures 10-16 : Intégration IA

Connecte l’API OpenAI. Itère sur les prompts avec des données réelles. C’est la partie la plus critique.

⚠ Si l’IA ne marche pas, le MVP n’a pas de valeur
H16

Heures 16-28 : Frontend

Construis l’interface avec shadcn/ui. Landing, page produit, résultats. Pas de design custom.

H28

Heures 28-36 : Auth + Paiement

Supabase Auth (login Google en 30 min). Stripe Checkout si nécessaire. Simplicité maximale.

H36

Heures 36-44 : Tests + Corrections

Teste le flow complet. Invite 2-3 personnes. Corrige les bugs critiques uniquement.

H44

Heures 44-48 : Polish + Déploiement

Méta-tags, favicon, dernier test en production sur Vercel. C’est prêt.

Les 3 pièges à éviter

🎨

Perdre 4h sur le CSS

Utilise shadcn/ui tel quel. Pas de design custom pour un MVP. Le design viendra en V2.

🔄

Refactoriser en cours de route

Le code n’a pas besoin d’être parfait. Il doit fonctionner. La refacto, c’est après la validation.

🛠

Gérer tous les edge cases

Si ça marche pour le cas nominal, c’est suffisant. Les cas limites attendront la V2.

Règle d’or : découpe en petits morceaux. Un composant, une route, une fonction. Vérifie chaque morceau avant de passer au suivant.

Construis par couches

🗃

Couche 1 : Backend

Base de données + API Routes. Tout doit fonctionner et être testable avant le frontend.

🤖

Couche 2 : IA

Intégration OpenAI + itération sur les prompts. C’est le cœur de la valeur de ton MVP.

💻

Couche 3 : Frontend

Interface React + connexion aux APIs déjà fonctionnelles. Composants shadcn/ui prêts à l’emploi.

Ne passe jamais au frontend tant que les APIs ne fonctionnent pas. Construire un frontend sur des fondations instables = perte de temps garantie.
